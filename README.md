# Прогноз потока гостей

Проект прогнозирует число гостей ресторана на следующие семь дней по дневной истории посещаемости.

Для работы используется синтетический датасет из трёх ресторанов за период с 2024-01-01 по 2026-09-30. Целевая переменная это `guests`, число гостей за день.

## Данные

Синтетический ряд создаётся скриптом `data/raw/generate_dataset.py` с фиксированным `RANDOM_STATE = 42`.

В генераторе заложены недельная и годовая сезонность, разные уровни спроса и тренды для ресторанов, праздничные всплески, плановые закрытия, технические закрытия, пропущенные календарные дни, частичные пропуски и аномальные значения.

В `data/raw/dataset.csv` находятся 2 958 наблюдений. В `data/processed/dataset.csv` находятся 3 012 наблюдений, по 1 004 дня для каждой точки.

Закрытый день сохраняется как наблюдение с нулевыми `guests` и `revenue`. Пропуск в выгрузке восстанавливается как отсутствующая дата или пропущенное значение. Периодов полного отсутствия точки в данных нет. Календарь для каждой точки восстанавливается только между её первой и последней наблюдаемыми датами, поэтому даты вне периода работы точки не заполняются.

## Подготовка данных

Логика подготовки находится в `src/data.py`.

Пропущенные календарные дни восстанавливаются с дневной частотой. Пропуски `guests` и `revenue` заполняются медианой для сочетания ресторана и дня недели. Если такой медианы нет, используется медиана ресторана, затем общая медиана.

Статистики для заполнения пропусков и границы выбросов рассчитываются только на части данных до validation периода. Это не позволяет информации из будущего повлиять на оценку модели.

Для каждого ресторана ограничиваются только верхние экстремальные значения по границе `Q3 + 3 * IQR`. Низкие значения и нулевые дни не ограничиваются, потому что они могут отражать реальное падение спроса или закрытие ресторана.

## Признаки и модель

Признаки строятся в `src/features.py` и используются одинаково при обучении и при прогнозе.

Используются день недели, циклическое представление месяца, признак праздника, лаги за 7, 14 и 28 дней, а также скользящие средние за 7 и 28 дней. Скользящие средние сдвинуты на 7 дней. Поэтому все признаки доступны для каждой даты семидневного прогноза без подстановки будущих значений `guests`.

Отдельный признак выходного дня не используется. День недели уже однозначно определяет выходные и содержит больше информации.

Модель реализована в `src/model.py`. Используется Ridge регрессия в `scikit-learn` Pipeline. Числовые признаки масштабируются, бинарный признак праздника передаётся без преобразования, а ресторан и день недели кодируются через One Hot Encoding.

## Валидация и результаты

Валидация находится в `src/validation.py`. Последние шесть недель с 2026-08-20 по 2026-09-30 используются как отложенный период. Все более ранние даты входят в обучение. Перемешивание не применяется.

Бейзлайн повторяет число гостей того же дня недели неделей ранее через `lag_7`.

| Модель | MAE | MAPE |
| --- | --- | --- |
| Ridge | 15.82 | 23.18% |
| Бейзлайн `lag_7` | 20.06 | 30.28% |

Ridge уменьшает MAE на 4.24 гостя или на 21.14% относительно бейзлайна.

MAE показывает среднюю абсолютную ошибку в гостях и понятна для планирования смен и закупок. MAPE показывает относительную ошибку и позволяет сравнивать качество на днях с разным спросом. Нулевые дни исключаются из MAPE, потому что процентная ошибка при нулевом фактическом значении не определена.

Для обычных дней средняя ошибка около 16 гостей может быть полезна как ориентир при планировании. Для дней с редкими локальными провалами и всплесками прогноз стоит дополнять ручной проверкой, потому что без данных о погоде, акциях, банкетах и других событиях модель склонна сглаживать такие изменения.

## Что это значит для бизнеса

Средняя ошибка около 16 гостей. Загрузка ресторана в среднем 60–100 гостей в день, то есть ошибка составляет примерно пятую часть потока. На практике это означает, что запас по гостям ±16 не критичен для закупок, но для планирования смен его недостаточно как единственного ориентира. Имеет смысл держать 1–2 сотрудника в резерве на смены с прогнозом выше среднего. Модель полезна для планирования уровня загрузки (low / normal / high), а не точного числа гостей. На праздничные дни и локальные аномалии полагаться нельзя: там ошибка может достигать 50+ гостей. Такие дни требуют ручной корректировки.

## Запуск

Нужен Python 3.11 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Чтобы заново сгенерировать исходные данные и подготовить датасет, выполни команды.

```powershell
python data/raw/generate_dataset.py
python -m src.data
```

Обучение, оценка модели и сохранение файла `models/ridge_model.joblib` выполняются в `notebooks/02_modeling.ipynb`. Ноутбук нужно открыть из корня проекта и выполнить все ячейки.

Прогноз для ресторана 1 с 2026-10-01 выполняется так.

```powershell
python predict.py --date 2026-10-01 --restaurant 1
```

Скрипт выводит семь строк с датой, идентификатором ресторана и прогнозом числа гостей. Он использует только наблюдения раньше переданной даты и загружает сохранённую модель без повторного обучения.

Чтобы сохранить прогноз в CSV, можно передать путь.

```powershell
python predict.py --date 2026-10-01 --restaurant 1 --output data/predictions/restaurant_1_forecast.csv
```

Тесты признаков запускаются командой.

```powershell
python -m pytest
```

